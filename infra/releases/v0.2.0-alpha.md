# Legacy v0.2.0-alpha release notes

Cut 2026-07-04 at BUILD_ORDER step 22 (MVP-022 acceptance run and MVP-023
spec sync). Specification repository version 0.4.0 (see
[CHANGELOG](../../CHANGELOG.md)). This is an alpha: everything below runs
and is test-verified on the reference environment; production provisioning
is the explicit remaining gap, itemized at the end.

## What ships

**Foundation (steps 1 to 12).** Monorepo scaffolding with environment
identity; CI with the full quality-gate ladder; the complete 35-table
schema as hand-written migrations with the never-auto-upgrade tier guard;
OIDC resource-server authentication with mandatory owner MFA and personal
access tokens (hash-only, expiring, revocable, audited); the deny-by-default
policy service with privacy-tier ceilings, grants, and agent hard-denials;
the /v1 conventions layer (one error envelope, cursor pagination,
Idempotency-Key replay, rate limiting, provenance blocks); structured
logging with content redaction, log-emitted tracing, Prometheus metrics,
and the SEV alert router; encrypted backups with owner-key escrow
discipline; the ingestion pipeline (preservation before parsing, checksum
dedup, review flags); quick capture and the workspace shell.

**Knowledge and truth (steps 13 to 20).** MASTER_CONTEXT seeded as 72
tiered Claims with full provenance (idempotent, audited); the owner
document batch importer (repository corpus imported; personal batch
deferred by owner decision); revision history and soft delete with undo;
chunking and embeddings behind the Model Router with the ADR-16 pinned
model and version-scoped indexes; tier-filtered lexical, semantic, and
RRF-fused hybrid search (ADR-17) with the golden-set baseline; the search
UI with text-labeled provenance badges and citation chips; the
verification queue where only the owner moves tiers, through step-up, the
policy service, and the database tier guard.

**Hardening (steps 19 and 21).** Measured performance baselines
([PERFORMANCE_BASELINE](../PERFORMANCE_BASELINE.md)); runbooks 1, 2, 3,
and 5 automated with object storage in backup coverage; the go-live
checklist ([GO_LIVE_CHECKLIST](../GO_LIVE_CHECKLIST.md)) and the Gate G1
evidence log ([G1_EVIDENCE](../G1_EVIDENCE.md)).
